## What counts as a security issue

- browser or PWA vulnerabilities in the public site
- service worker or cache behavior that leaks data
- privacy problems in consent or browser storage handling
- unsafe exposure of site content or metadata

## What is not a security issue

- broken streams controlled by third-party radio providers
- content errors in playlists without a security impact
- ordinary browser bugs without a data exposure path
- feature requests

## Reporting a vulnerability

Please do not report security vulnerabilities through public GitHub Issues.

Use GitHub Private Vulnerability Reporting:

1. Open the repository's Security tab.
2. Select Report a vulnerability.
3. Provide the affected page, browser, reproduction steps, impact, and any relevant screenshots or console output.

If the Report a vulnerability option is not available, do not publish the details publicly. Contact the repository maintainer through an existing private channel and ask for a secure reporting method.

Please include a short description, affected page, browser, and whether the problem is reproducible in a private window.

## Scope

The supported scope is the public website and its generated assets.
Third-party radio streams are outside full control, but site behavior around them is in scope.

Private Vulnerability Reporting is the preferred reporting path when available.
