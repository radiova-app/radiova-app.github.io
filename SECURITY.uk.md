# Політика безпеки

English | Українська | [Deutsch](SECURITY.de.md)

Цей репозиторій містить лише згенерований вміст GitHub Pages.
Джерело правди: `radiova-platform-private/apps/web`
Опублікований результат: `docs/`

Не редагуйте файли всередині docs/ вручну. Їх створює production-збірка приватного monorepo.

## Що вважається проблемою безпеки

- вразливості браузера або PWA у публічному сайті
- поведінка service worker або cache, що може витікати дані
- проблеми приватності в consent або обробці browser storage
- небезпечне розкриття контенту або метаданих сайту

## Що не є проблемою безпеки

- зламані потоки від сторонніх провайдерів радіо
- помилки в плейлистах без впливу на безпеку
- звичайні баги браузера без витоку даних
- запити на нові можливості

## Повідомлення про вразливість

Не повідомляйте про вразливості через публічні GitHub Issues.

Використовуйте GitHub Private Vulnerability Reporting:

1. Відкрийте вкладку Security цього репозиторію.
2. Виберіть Report a vulnerability.
3. Додайте сторінку, браузер, кроки відтворення, вплив і, якщо потрібно, скриншоти або вивід консолі.

Якщо пункт Report a vulnerability недоступний, не публікуйте деталі відкрито. Зверніться до мейнтейнера через наявний приватний канал і попросіть безпечний спосіб повідомлення.

Додайте короткий опис, сторінку, браузер і чи відтворюється проблема в приватному вікні.

## Сфера дії

Підтримувана сфера - публічний сайт і згенеровані артефакти.
Сторонні радіопотоки не повністю під нашим контролем, але поведінка сайту навколо них входить у сферу.

Private Vulnerability Reporting є бажаним каналом повідомлення, коли він доступний.
